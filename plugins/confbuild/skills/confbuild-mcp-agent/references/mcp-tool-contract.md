# confBuild MCP tool contract

## Shared customer loop

- The installed plugin reads the packaged `references/model-loop.md` snapshot and starts sessions with `workflowSource: 'plugin'`; the server then omits runtime behavioral instructions.
- Direct MCP-only clients receive `references/model-loop.md` plus a compact Sheet-generation core in the default progressive bundle. They then load the selected profile and only the semantic prompt packs needed for the planned row types through `confbuild_get_prompt_sections`; explicit `essential`/`full` requests retain the legacy monolithic bundle.
- Both paths therefore use the same acceptance, native-part, validation, multi-view review (four default views, up to seven), repair, and stop-gate contract, but only an explicit plugin release changes an installed plugin's behavioral workflow.
- Local repository generators, Playwright artifact workflows, service accounts, and subagent requirements are intentionally outside the customer loop.

## Toolsets

- A connection lists one toolset: `modeling` (default; every project, render, export and comparison tool), `video` (the video studio tools plus the shared basics) or `all`. Select it with `?toolset=video|all` on the hosted MCP URL (`https://app.confbuild.com/mcp?toolset=video`) or `CONFBUILD_MCP_TOOLSET` for the local server; `confbuild_start_design_session` reports the active toolset. Tools outside the toolset are not listed and cannot be called on that connection.

## State boundaries

- A design session stores request/profile context. In hosted mode, the exact start-session request and latest committed Sheet snapshot are additionally written to admin-only audit history; client reasoning, model messages, screenshot analysis, screenshots, and final free-text summary are excluded.
- Before create, the design session stores a mandatory `confbuild_plan_sheet_topology` result; begin-edit adopts the project's saved plans and clone adopts its source's saved plans (explicit manufacturing plan and `scriptcode` included) when the session has none, so an unchanged plan is never restated. A re-plan that sends `plan` without `manufacturingPlan`/`manufacturingPlanPatch` keeps a saved explicit manufacturing plan (`preservedSavedManufacturingPlan: true`); only a project without one gets the `sheet-derived-legacy` fallback. `single-sheet` is reserved for one indivisible part. A `composite` plan declares the first orchestration sheet plus named functional `SHEET:`/`PROJECT:` children, parent ownership, repeated status, local datum, and child-specific input ids. Project creation seeds every planned embedded sheet immediately; the plan is copied into the edit session and may be revised explicitly by calling the same tool with `editSessionId`; change an existing manufacturing plan with `manufacturingPlanPatch` (see Incremental manufacturing plan updates).
- An edit session stores a full hydrated workbook and its base storage revision in MCP-server memory. Every write to it is a compare-and-swap on the stored generation: two calls that loaded the same session concurrently cannot overwrite each other; the later one receives `EDIT_SESSION_CONFLICT` and must re-read. Never run two tool calls against one edit session in parallel.
- Sheet patches are local until `confbuild_commit_edit` or the composite `confbuild_publish_checkpoint` fast path.
- Deterministic repairs are operations, not prose: `wire_child` writes or repairs the parent `SHEET: <child>` row with a governing `#` header that passes every planned child input (every `TOPOLOGY_CHILD_REFERENCE_MISSING`/`TOPOLOGY_REFERENCE_PARAMETER_MISSING` error carries the exact `suggestedOperation`); `set_default_material` fills `mechanicalMaterialId` on every physical row that has none (`PHYSICAL_MATERIAL_MISSING` carries a library `suggestion` per row type where one exists; building and furniture rows get none); `auto_fix` (or `autoFix: true` on patch/checkpoint) repairs `VALIDATED` same-row formulas, `groupend` cells, control-type aliases, derives manufacturing metadata from the plan and runs `wire_child` for every missing reference or reference parameter the plan determines unambiguously; the topology errors it cannot resolve keep their exact `suggestedOperation` plus `autoFixable`, `autoFixBlocker` and `parametersNeedingValue`. A child `auto_fix` wired sits at the parent origin under `<child>_1`: move it with `wire_child` on that outputId instead of adding a second row; `wire_child` repairs keep the cells a row already passes unless `parameters` overrides them. Every rewrite the server performs, including the silent 0/1 number-to-checkbox normalization, is listed per row in `normalizations`.
- `ROW_TYPE_HEADER_MISMATCH` warns when an output row sits under a `#` header that lacks its primary column and leads with another type's column (a `cylinder` under a `cube` header): the engine maps cells by position and builds degenerate geometry without any message. Start a `#` header for that type directly above the row.
- Installed-plugin sessions may load knowledge sections through `confbuild_get_prompt_sections` (`pack-*`, `machine-domain-guide`, `machine-parts-guide`, `placement-conventions`, `profile-*`); only the behavioral workflow sections stay refused.
- Inspection evidence is bound to the exact revision, not to the design session: a new session on an unchanged project reuses the four-mode evidence of the previous one for seven days; any commit invalidates it.
- Retries are safe when they carry ids: `mutationId` on `confbuild_apply_sheet_patch`/`confbuild_publish_checkpoint`/`confbuild_commit_edit` makes a repeated call acknowledge the already applied/committed mutation (`alreadyApplied`/`alreadyCommitted: true`) instead of applying it twice; `confbuild_create_project` defaults its `idempotencyKey` to the design session, so a retried create resolves to the same project; an identical render/export of the same revision that is still running is returned as `reused: true` instead of being queued again.
- Long initial builds use adaptive coherent checkpoint commits as the progress channel. `confbuild_publish_checkpoint` combines patch, fingerprint-cached validation, revision-protected commit, and an in-place rebuild in the already connected clean editor tab. By default (`waitForEditorMs: 0`) it returns right after the atomic save: `editorUpdate.inProgress`/`editorRevisionPending: true` mean the clean tab accepted the revision and rebuilds in the background, `nextTool` is the normal stage continuation, and render/inspect/interaction/export calls wait briefly for the exact revision and then queue behind the rebuild (`editorRevisionPending` on the poll). No `confbuild_prepare_browser` turn is needed unless a later result returns it as `nextTool`, reports `BROWSER_TAB_REQUIRED`/`BROWSER_CONNECTION_REPLACED` or names a user action. Invalid in-memory edits are retained for repair but never exposed as previews; a dirty tab refuses the update.
- Commits use the authenticated owner's private Firestore path and reject a changed base revision.
- Workbook validation returns a `topology` block and applies the declared plan as a commit gate. It rejects a missing/not-first main sheet, missing or unplanned child sheets, missing exact parent references, planned child inputs absent from the child or parent reference row, under-instantiated repeated children, and cyclic `SHEET:` graphs. Orphan child sheets are warnings even without a plan. `completionState=complete` additionally requires final scene diagnostics to name every planned embedded child and prove the planned subproject count.
- Large workbooks use a new generation-specific chunk prefix. The project manifest and its chunks are written atomically; older project-sheet chunks are cleaned afterward.
- Each commit stores the pre-commit workbook and project `scriptcode` together as a rollback snapshot in the same embedded-sheet subcollection under a dedicated scope; retention keeps the newest snapshots and prunes the rest after every commit. Snapshot protection is mandatory: legacy `snapshot: false` input is accepted but ignored, and a snapshot failure blocks the commit. Legacy workbook-only snapshots remain readable and explicitly preserve the current `scriptcode` when restored.
- Browser presence is the live preview, semantic-interaction, and capture channel, not the normal authoring surface. The connected app tab rebuilds MCP-authored revisions, claims interaction/render/screenshot jobs, and shows checkpoints to the user. Before a new project exists, `confbuild_prepare_browser` proves the assigned signed-in tab or a reusable dashboard or returns a dashboard `open-new` handoff. Once a target exists, it compares the exact project/configuration/revision with signed-in tab presence and returns the least disruptive `reuse`, `reload`, `navigate`, or initial `open-new` action (safe recovery replacements follow SKILL.md). The server records that open request per design session; while the tab is loading, later prepares return `tab-opening`/`reuse` instead of another `open-new`. Once any matching project/configuration tab exists, it is reused; the in-place rebuild discards its unsaved changes (`discardsUnsavedChanges`) without asking the user or opening a duplicate. When several host tabs are visible, the host enumerates them and selects by exact project/configuration URL; the active, newest, or first-listed unrelated tab has no priority. The host retains that selected tab handle per design session, performs the tab-lifecycle action or the documented recovery exception, and repeats the call until `connected: true`; it never clicks editor controls, types project data, submits the prompt editor, or invokes page functions during normal operation. Project-authored INPUT buttons and named project/VBA functions/actions are exercised only through `confbuild_run_project_interaction`, whose backend-resolved selector is bound to the exact revision; it is not authorization for raw DOM clicks or arbitrary page evaluation. A different project/configuration tab is never repurposed or overwritten. Create requires the signed-in tab. Begin-edit, clone and restore are data operations: with no tab open for the project they proceed and return `browserConnection: null` (prepare once before the first checkpoint, render or interaction; begin-edit then returns `nextTool: 'confbuild_prepare_browser'` with `afterBrowserConnection: 'confbuild_publish_checkpoint'`, because checkpoints still commit through the tab); a tab for that project in a dirty, unknown or user-owned state still blocks them so unsaved work survives. Restore also accepts a saved revision that no longer builds; the restore is the repair. Commit/checkpoint need the connected tab but accept a live, clean matching tab with a pending/failed model so a repair can be saved. Interaction/render/export still require the exact ready model. `browserConnected`, `modelReady` and `repairCanBeSaved` distinguish these states; `modelUpdates` identifies the automatic editor command and requires no user approval.
- The prepare-browser resource link is the agent navigation target and a manual fallback only for an actual user-action blocker. Follow SKILL.md Autonomous connection recovery, including its safe reload/replacement exception. Older server deadline/lifetime-tab prose is legacy client guidance; keep waits at most 25 seconds and honor actual backend gates. Match origin, project and configuration while ignoring transient query/hash fields.
- Tab presence carries `visibilityState`/`visibilityChangedAtMs` and a heartbeat (`lastSeenAtMs`, refreshed every 20 s by a worker clock that also runs in hidden tabs). Hidden tabs keep rebuilding, claiming and capturing, so visibility alone never triggers a user action. An assigned tab without heartbeat for 75 s (server-side write time) is replaced once before anyone is asked: `confbuild_prepare_browser` adopts an open, unassigned matching tab (`previousTabId`/`replacedStalledTabId`) or returns `state: 'tab-stalled'`, `action: 'open-new'` for exactly one new tab; while that tab loads, later prepares return `tab-opening`; render polls on the stalled tab report `tabStalled: true` with `nextTool: confbuild_prepare_browser`, and a job started after the switch targets the new tab. `userActionRequired: 'focus-tab'` plus `userAction.instruction` appears on a non-connected handoff, a `BROWSER_TAB_REQUIRED` error or a running render/inspection poll only when the replacement did not connect within 4 min or stalled again within 30 min, when known pending work (in-place rebuild, unclaimed job) waited 3 min while a responsive tab stayed hidden, or when a job expired unfinished while hidden; a connected stalled tab without an assigned session stays usable for edits and commits but reports `renderRequiresVisibleTab: true`. A job that failed with its own error is never attributed to visibility. Bring that confBuild tab to the front yourself (macOS in this repository: `scripts/mcp-focus-confbuild-tab.sh <projectId>`, which selects the tab and never switches the app in front; a Chrome started through the `Chrome MCP` starter keeps covered windows working; otherwise the host's browser or desktop control, without taking the user's keyboard focus) and ask the user, once and in their language, only when no such control exists or it did not help; reloading or opening another tab does not help. The server does not wait on a handoff that names a user action.
- When the assigned tab reloads or navigates back to the project, its route connection id rotates. If the same user still has exactly one live, clean tab on the session's exact project/configuration (the same physical tab with a new connection id, or a single reopened tab not owned by another session), the server rebinds the design session inside the running call and reports it as `browserConnectionAdoption` on the next `confbuild_prepare_browser`; only an ambiguous or missing replacement still fails with `BROWSER_CONNECTION_REPLACED`.
- Multiple AI slots and MCP transport connections are supported concurrently. Each slot uses its own `designSessionId`, edit session, and retained exact project/configuration tab handle; there is no global active MCP tab. Independent sessions/projects may progress in parallel, but two mutations against the same edit session are rejected/serialized through its generation contract.
- The owner-visible editor connection record is per design session, not merely per OAuth client. It contains bounded ephemeral identity metadata only: MCP client name, reported agent client/model, optional host-provided `sessionLabel` (set at start or updated later through `confbuild_prepare_browser`), `designSessionId`, assigned tab id, project id, activity timestamps, and current tool. When no label is available, the editor shows a short session-id fallback. It contains no prompt, Sheet values, model messages, or reasoning and expires with the session.
- A UI mutation fallback is disabled by default. It requires a structured MCP result proving the exact semantic capability is unsupported, confirmation that no MCP tool covers it, and explicit user approval for one bounded UI action. Errors, timeouts, missing tabs, or browser unavailability never activate it. Return to MCP afterward. The confBuild AI prompt editor and provider-backed generation endpoints are never fallback surfaces.
- Render jobs are asynchronous so MCP client tool timeouts do not terminate browser work. `confbuild_get_render_result` long-polls server-side with `waitMs` (default 25 s, max 120 s — pick a value below your client's own tool timeout); a still-running answer carries `retryAfterMs` and the exact next call. Never start a second job for the same revision while one runs: a capacity refusal (`HEADLESS_USER_CONCURRENCY_LIMIT`) lists `activeJobIds` to keep polling. `diagnosticsOnly: true` builds the committed revision without screenshots and returns only the audit blocks — run it after checkpoints, never as a substitute for the visual review. Browser-tab rendering is the default and never falls back to server compute. `rendererMode: 'server-headless'` is valid only after an explicit user request, requires `serverRenderingExplicitlyRequested: true`, and still requires the exact browser connection.
- From the `interfaces` stage on, a checkpoint starts an asynchronous diagnostics-only engine check by default (`engineCheck: 'async'`; `engineCheck: false` for the early stages, `true` waits in the call). The result arrives as `previousEngineCheck` on the next patch, checkpoint or `confbuild_validate_edit` result: `rowsWithoutGeometry`, actionable engine warnings, placement audit and defect signals, reported once.
- `confbuild_finish_design_session` with `dryRun: true` evaluates every completion gate for `completionState` (default `complete`) and returns all `blockers` with their `nextTool` plus the `passedGates`, without closing or recording anything. Run it after the last commit and before the inspection sweep and the final render.
- `confbuild_run_project_interaction` is a non-idempotent browser-tab job for persisted project behavior. `type: 'input-button'` resolves an exact `INPUTID`/optional sheet and executes only its stored `ONCLICK` or registered VALUE action; `script-function` accepts only a bare declared function name; `script-action` accepts only a registered action id. It awaits the callback, optionally observes delayed motion, returns before/after images, changed output transforms, active-animation summaries, and script debug/error evidence, and continues through `confbuild_get_render_result` if the first wait expires. Never pass or synthesize arbitrary JavaScript expressions.
- A failed browser-tab job keeps the family code `RENDER_FAILED`/`PROJECT_INTERACTION_FAILED` and adds `failureCode` (`JOB_EXPIRED_UNCLAIMED`, `JOB_EXPIRED_WHILE_CAPTURING`, `MODEL_NOT_READY`, `CAPTURE_BLANK`, `BROWSER_TAB_DIRTY`, `CONFIGURATION_CHANGED`, …), `failureStage`, `lastJobStatus`, the target tab's `tabVisibility`, and a concrete `nextTool` or `userActionRequired`. Follow that step instead of a blind retry.
- Render diagnostics include an approximate geometry audit, exact and unverified intersection findings, `outputIdAudit.rowsWithoutGeometry`, engine warnings, `diagnostics.scene.parts`, and `diagnostics.scene.subsheets` with exact child name, instance output id, descendant ids, mesh count, and world bounds. The `qualityGate` returns separate local output-id groups plus `requiredSubsheetNames`, `missingSceneSubsheetNames`, `remainingInspectionSubsheetNames`, and `suggestedInspectionSubsheetNames`. Every planned child sheet and every required defect/connection group needs revision-bound four-mode evidence; evidence for another target does not satisfy the completion gate. Render results default to `diagnosticsDetail: 'summary'` (counts plus capped samples; gate verdicts always use the full diagnostics); poll the same renderJobId with `diagnosticsDetail: 'full'` when a repair needs every collision pair, part bound or descendant id.
- `diagnostics.geometry.intersectionFindings` carries the engine's exact intersection preflight (OBB-SAT/CSG member overlaps) including a concrete fix `suggestion` per pair (which member yields, the exact `trimby=` cell to add). Treat these as first-class repair instructions — they are the same gate the local composite loop uses — and prefer them over re-deriving overlaps from screenshots.
- With the same project open in several tabs, a per-job claim lease makes exactly one tab capture; a tab that dies mid-capture is taken over after its lease expires.
- Edit sessions carry the project's saved configuration state so validation can flag VALUE cells that the editor will override (`VALUE_SHADOWED_BY_CONFIGMODEL`).
- The finish tool stores only content-free outcome enums (completion state, iteration count, fixed/residual defect categories); the free-text summary, `residualFindings`, and user-facing `residualReport` are never persisted in the audit log. For partial results pass the last completed render plus `stopReason` (`budget-exhausted`, `no-progress`, `user-requested`, or `blocked`). The report returns named pair evidence, total counts/truncation, and a continuation question. Include visual findings missed by diagnostics. Ask the user before extending an exhausted loop; resume with a fresh session on the same project URL after approval.
- Hosted usage telemetry stores content-free operational measurements only: authenticated user/client IDs, timestamps, tool/status/error code, duration, byte counts, Sheet operation/row/cell quantities, commits, project IDs, render/export jobs, and actual returned image/artifact blocks. Metadata-only screenshot descriptors are not counted as delivered images. Detail events expire after 90 days; daily per-user aggregates remain for trends. Client-side model tokens are not observable.
- MCP project provenance stores created/edited state, timestamps/count, agent client, optional client-reported model, profile, and MCP client name/version. It stores no prompt, Sheet values, screenshots, responses, or reasoning.

|---|---|---|
| Orient | `confbuild_start_design_session` | Session ID plus display identity (client/model, optional exact host `sessionLabel`, short-ID fallback), effective profile, plugin-version status, target/editability, next tool; direct MCP-only callers additionally receive the server prompt bundle |
| Plan | `confbuild_plan_sheet_topology` | Mandatory pre-mutation contract choosing one indivisible sheet or a Composite-Loop-style `Main Part` plus exact functional children, local datums, repeat rules, and per-child inputs; returns seeded embedded-sheet names and can revalidate an existing edit |
| Orient | `confbuild_get_prompt_sections` | Session-bound progressive loading of the required profile and selected semantic knowledge packs; known section hashes suppress cached text |
| Resolve | `confbuild_resolve_project_reference` | Private/public locator without guessed owner paths; `includeSheets` is windowed like `confbuild_read_project` (`maxCharacters`) |
| Create | `confbuild_create_project` | User-owned private project and editor URL |
| Clone | `confbuild_clone_project` | Editable private copy of public/read-only source with its sheet plan, explicit manufacturing plan and `scriptcode`; runs without an open tab |
| Connect | `confbuild_prepare_browser` | Signed-in browser proof before creation, then exact-revision proof plus safe handoff/resource link. Call it only after create/clone/restore, before the first render/inspection/interaction while no tab is connected, and when a result returns it as `nextTool`, `BROWSER_TAB_REQUIRED`, `BROWSER_CONNECTION_REPLACED` or `userActionRequired` (including after the user acted on `'focus-tab'`); repeat until `connected: true`. Never a routine step after a checkpoint or commit. Accepts `sessionLabel` to set or update the badge label once the host exposes the chat title |
| Orient | `pack-machine-elements` (via `confbuild_get_prompt_sections`) | Row formats and parameter tables for the 40 native row types the canonical catalog omits (gear, rack, bearing, sprocket, coupling, hinge, iecmotor, gearmotor, linearguide, energychain, sheetmetal, …); recommended for the machine profile, loadable in `maxChars` windows |
| Orient | `confbuild_explain_row_type` | Canonical header columns, example rows, placement notes, and the repository documentation excerpt for one row type (gear, aluprofile, pneumatic, sheetmetal, …) — cheaper than loading the whole catalog pack |
| Inspect | `confbuild_read_project` | Hydrated workbook; filter by `sheetNames`, page with `startRow`/`maxRowsPerSheet` (unknown names error with the available list); `format: 'tsv'` returns each sheet as one tab-separated block at roughly half the tokens. Rows are windowed to `maxCharacters` (default 60 000): a cut answer reports `autoWindowed` and `nextStartRow`, so continue with `startRow` or narrow `sheetNames`. `includeMenuSettings: true` adds the public-viewer options (lead webhook and e-mail redacted) |
| Edit | `confbuild_begin_edit` | Edit ID, base revision, workbook windowed like `confbuild_read_project` (filter with `sheetNames`/`maxRowsPerSheet`, `format: 'tsv'`, or `summaryOnly: true` when you already read it; page further with `confbuild_read_edit_workbook`), `manufacturingPlanSummary` (full plan with `topologyDetail: 'full'`); runs without an open tab |
| Patch | `confbuild_apply_sheet_patch` | In-memory workbook operations (including `wire_child`, `set_default_material`, `auto_fix`), immediate validation, `normalizations` for every server-side rewrite, `previousEngineCheck` when an asynchronous engine check finished, and progressive-preview guidance. `stageComplete: true` plus `previewStage` marks a coherent checkpoint; `mutationId` makes a retry idempotent; `autoFix: true` appends the mechanical repairs |
| Publish | `confbuild_publish_checkpoint` | Preferred stage fast path: patch + one cached validation + atomic workbook/`scriptcode` save + mandatory rollback snapshot + in-place editor rebuild that runs in the background (`editorRevisionPending: true`; pass `waitForEditorMs` only when the response itself must prove `visibleInEditor: true`). Every successful stage is a persistent recoverable revision |
| Gate | `confbuild_validate_edit` | Errors and warnings: declared composite topology and child parameter contracts, structure, formula analysis (parse traps, `,` separators, row-1/beyond-sheet refs, cycles), SHEET:/PROJECT: reference resolution, row-type catalog check with typo suggestions, header-column typos against the catalog (`UNKNOWN_HEADER_COLUMN`), decimal-comma literals (`DECIMAL_COMMA_LITERAL`: `1,5` is parsed as 1), unresolved same-sheet references in `refpos`/`profile1`/`profile2`/`cuttedoutputid`/`from`/`to` (`UNRESOLVED_OUTPUT_REFERENCE`), naked cell references inside contour strings (`CONTOUR_CELL_REFERENCE_LITERAL`), the sheet-metal subset (`SHEETMETAL_THICKNESS_INVALID`, `SHEETMETAL_KFACTOR_RANGE`, `SHEETMETAL_BEND_RADIUS_SMALL`, `SHEETMETAL_CONTOUR_INVALID`, `SHEETMETAL_BENDS_INVALID_JSON`), canonical INPUT control types, same-row VALIDATED formulas, slider bounds/step, select/radio choices, button actions, layout-only fields, and matched `groupend` structure, slider-first numeric-input policy (`NUMERIC_INPUT_SHOULD_USE_SLIDER`), input MIN/MAX plausibility, engine-trap lint, configmodel shadowing |
| Persist | `confbuild_commit_edit` | Atomic revision-protected workbook/`scriptcode` save, mandatory pre-commit rollback snapshot, new revision. A failed validation or snapshot leaves the saved project unchanged |
| Scene | `confbuild_update_scene_settings` | Reads and writes `project.sceneSettings`: ambient/hemisphere/sun light, sun mode and position or date/time/site, environment map, background, fog, realistic rendering, edge mode, and the view/published toggles. Omit `sceneSettings` to read current plus effective values and the writable catalog; pass a partial patch to change only those keys. Revision-protected, returns the previous values as the rollback, and re-applies the look in the connected tab without a model rebuild |
| Recover | `confbuild_list_project_snapshots` | Rollback snapshots of an owned project, newest first |
| Recover | `confbuild_restore_project_snapshot` | Commits a stored workbook plus `scriptcode` snapshot back; the pre-restore state is snapshotted first. Legacy workbook-only snapshots preserve current source. Runs without an open tab and on a saved revision that no longer builds |
| Recover | `confbuild_diff_revisions` | Row-level Sheet diff plus content-free `scriptcode` SHA-256/byte comparison between a snapshot and the current revision or another snapshot |
| Render | `confbuild_render_and_wait` | Starts browser-tab rendering and long-polls it in one call; `waitMs: 0` only starts the job and returns its `renderJobId` for `confbuild_get_render_result`. `views` accepts `default`, `right`, `front`, `left`, `back`, `top`, `bottom`; default is the four-view review set, a single targeted view saves tokens on a re-check. Server-side Chromium runs only with explicit user opt-in via `rendererMode: 'server-headless'` |
| Inspect | `confbuild_inspect_outputs` | One revision-bound four-image analysis set for either exact `outputIds` or exact embedded `subsheetNames` (never mix target families in one call): zoomed opaque target with ghosted surroundings, isolated front view, automatic target-center section, and x-ray. Composite completion requires every planned child name; geometry defects and structural connections remain separate local groups. A row id repeated in many SHEET instances is named per instance by an occurrence path (`aPath`/`bPath`, e.g. `g10/channel`); pass the suggested paths unchanged. Bare ids whose instances share no readable frame are shown on one representative instance each (`qualityGate.representativeInspectionFrames`). Follow every returned call before repair or completion |
| Interact | `confbuild_run_project_interaction` | Runs one exact persisted INPUT button, bare named project/VBA-script function, or registered script action in the connected revision; returns before/after screenshots, changed-output/animation state, and script diagnostics. Use it for Start and Stop controls instead of raw browser clicks or page evaluation |
| Scope | `captureScope` (on `confbuild_render_and_wait`) | `isolateOutputIds`/`zoomToOutputIds` target built output subtrees; `isolateSubsheetNames`/`zoomToSubsheetNames` target exact embedded `SHEET:` names. `ghostOtherObjects` keeps the focus opaque, `sectionPlane` accepts exact coordinates or `{axis: 'auto', position: 'target-center'}`, and `xray` exposes interiors. Unresolved output ids or subsheet names invalidate the evidence instead of silently accepting a whole-model frame |
| Review | `confbuild_get_render_result` | Long-pollable (`waitMs` default 25 s, max 120 s) ordered caption+image blocks plus scene/browser/geometry diagnostics, `outputIdAudit`, `engineWarnings`, `defectSignals`, iteration delta, and presentation metadata for Codex/Claude. Request `includeImages: true` with `maxImages` covering all views; `diagnosticsDetail` defaults to `summary`; request `full` only for complete finding lists |
| Export | `confbuild_export_project` | After browser preparation, starts an export through the app’s own exporters in the browser tab by default: `step` (simple/complex, exact OCCT B-reps where available), `ifc`, `stl`, textual `gltf`, binary `glb`, `3mf`, sanitized `bom-json`/`bom-csv`/`bom-xlsx`, `drawing-pdf`, `sheetmetal-dxf`, `cost-json`, `quote-pdf`, `purchase-json`/`purchase-csv`, `variant-metrics-json`, `dstv` (DSTV-NC steel fabrication ZIP, see “Steel fabrication (DSTV-NC)” below), `steel-plate-dxf` (one nesting DXF per steel plate position, derived from its NC file), or `steel-shop-drawings` (A3 PDF, one shop drawing per steel position drawn from its NC file, checked against it). Server-side execution is explicit opt-in only. Complex STEP can take minutes on large models |
| Export | `confbuild_get_export_result` | Long-polls the export job; embeds small files up to `maxContentBytes` (default 256 KiB, up to 20 MB on request) and directs larger files to the safe chunk tool without exposing private storage paths |
| Export | `confbuild_get_export_chunk` | Returns up to 4 MB from a completed export at `offsetBytes`; continue with `chunk.nextOffsetBytes` until `chunk.complete` |
| Compare | `confbuild_compare_variants` | After every reference was separately browser-prepared and its tab kept open, starts a sequential comparison of 2–8 distinct project or saved-configuration URLs by currency-safe price, fully covered mass, coverage-gated generic cradle-to-gate CO2e, or scene-axis X/Y/Z extent/volume. Saved configurations are accepted only at the exact document path and SHA-256 revision resolved when the job starts |
| Compare | `confbuild_get_variant_comparison_result` | Long-polls the comparison; successful variants remain rankable when another variant fails, and failed/insufficiently covered rows stay explicit instead of becoming zero |
| Search | `confbuild_find_rows` | Locates rows by cell content (substring/exact/safe regex, optional column filter) in an edit session or project — cheaper than reading whole sheets to find one row; page with `offset`/`nextOffset` |
| Resume | `confbuild_list_edit_sessions` | Lists live edit sessions (project, dirty state, commit count, expiry) so a lost `editSessionId` can be recovered instead of abandoning the session |
| Close | `confbuild_finish_design_session` | Final URL and structured content-free outcome; `dryRun: true` lists every remaining blocker first. `completionState: complete` is rejected unless the current revision has successful four-mode inspection evidence, the final render is unscoped with all four mandatory views, and no exact/unverified geometry blockers remain; partial/blocked sessions retain truthful residual categories |

Removed in 0.32.0: `confbuild_render_project` (use `confbuild_render_and_wait`, with `waitMs: 0` to only start the job), `confbuild_get_prompt_bundle` (the start-session bundle plus `confbuild_get_prompt_sections`), `confbuild_list_prompt_resources` (MCP `resources/list`) and `confbuild_browser_capabilities` (its `preferLocalTab` and `renderBudget` fields are in `confbuild_auth_status`).

Profile selection belongs to the MCP client: classify the request yourself and pass an explicit `profile` (`building`, `machine`, `3dprint`, `structure` for halls/frames/trusses, `furniture`, or `generic`). `auto` falls back to a server keyword heuristic intended only for clients that cannot classify. Installed plugins pass `workflowSource: 'plugin'` and receive no prompt bundle. Direct MCP-only clients keep the default `workflowSource: 'server'` and `promptDetail: 'progressive'`: read the compact base, call `confbuild_get_prompt_sections` for every `progressiveLoading.requiredBeforeEditing` id, then fetch only packs relevant to the actual design. `essential` and `full` remain available for compatibility. Clients may pass `knownBundleHashes` on repeat sessions so a matching base bundle returns without its text, plus `knownSectionHashes` so unchanged base or progressively loaded sections omit their text.

Error results carry machine-readable `structuredContent` with `code`, optional `retryable`, and context (for example the current revision on `REVISION_CONFLICT`, the available sheet names on `UNKNOWN_SHEET_NAME`, the existing project on `DESIGN_SESSION_HAS_TARGET`, or `activeJobIds` on `HEADLESS_USER_CONCURRENCY_LIMIT`). Every expected failure has a code; `INTERNAL_ERROR` means the server logged the details and a single retry is appropriate. Most responses also carry `nextTool` (plus `nextToolArguments`) for the recommended continuation. The hosted endpoint rate-limits per user (HTTP 429 with `retry-after`); long-polling with `waitMs` instead of rapid polling stays well inside the limits.

Commercial exports reuse the built scene’s canonical BOM, price, purchasing, and quote services. Quote and purchasing exports fail closed on mixed currencies; quote also fails on missing required prices, while purchasing outputs remain usable and report estimated-cost coverage for unpriced lines. No exchange-rate conversion is inferred. `quote-pdf` additionally requires a configured seller identity: a meaningful company or seller name in `companyName` plus either a complete postal contact (`street` and `zipCity`) or a valid electronic contact (`email`, `phone`, or `website`). Commercial failures expose machine-readable codes such as `INVALID_SELLER_IDENTITY`, `MIXED_CURRENCIES`, or `MISSING_REQUIRED_PRICES` plus PII-free details (field names, missing requirements, positions, or currency codes rather than seller/customer values). The CO2 comparison uses generic cradle-to-gate material factors rather than EPDs and reports coverage. Dimension sorts are explicitly scene-axis extents (`boundsX`, `boundsY`, `boundsZ`, `boundsVolume`), because width/depth/height conventions vary between projects.

Pass the start tool's `designSessionId` to `confbuild_create_project`, `confbuild_clone_project`, and `confbuild_begin_edit`. Hosted mode retains a latest-session fallback for older clients, but the explicit ID is required for correct association when one user runs concurrent agents. Pass the exact public model identifier to start-session `model` only when it is known, and the exact user-visible host task/thread/chat title to `sessionLabel` only when the host exposes it; never infer either. The editor uses the returned `sessionIdentity` and falls back to the short design-session id. Hosts often name a chat only after its first turn (Claude Code auto-titles sessions): pass the title to the next `confbuild_prepare_browser` call and the badge updates for the same design session. In Claude Code the title comes from the host's session tool (`get_session` with `self`); Codex exposes no thread title to the agent, so omit it there. Installed plugin skills also pass their bundled `pluginVersion`; the response's `clientPackage` block reports whether that version is current and supplies the host-specific update command when an update exists. Direct MCP-only clients may omit it. The server never silently changes local client files.

## Scene settings

- `project.sceneSettings` is the part of a project no sheet row can express. Sheet rows may add `ambientlight`, `directionallight`, `spotlight`, and friends, but the base ambient/hemisphere/sun lighting, the environment map every material samples through `scene.environmentIntensity`, the background, and fog all live on the project document.
- Therefore a negative light row is not a way to darken a scene. Only the ambient channel cancels exactly (it is constant per fragment); a negative directional cancels only at the identical bearing, and there is no negative environment map at all.
- Night, dusk, and a real time of day come from `sunMode: 'solar'` with `sunDate`, `sunTime`, `siteLatitude`, `siteLongitude`, and `siteTimezoneOffset`: a sun below the horizon fades the directional light out and dims the environment dome to a night floor. In `sunMode: 'manual'` the dome stays at full brightness whatever the bearing.
- Read before you judge: `confbuild_read_project` with `includeSceneSettings: true` returns stored values, the effective values the editor will use, and the writable catalog with types, ranges, and defaults. Unknown keys and out-of-range values are rejected with a per-key error instead of being written through.
- Write either with `confbuild_update_scene_settings` (settings only, no workbook rewrite, no rollback snapshot needed because the previous values come back in the result) or with `projectPatch.sceneSettings` on `confbuild_publish_checkpoint`/`confbuild_commit_edit` when the look changes together with the model. Both merge: keys you do not name keep their value.
- `sceneSettings.exposure` exists in old documents but no renderer reads it; it is not writable and changing it would do nothing.
- `sceneSettings.steelFabrication` (`drillConnectionHoles`, `exactChannelSection`) is the one setting that changes geometry: the open tab rebuilds the model. New projects start with both on; a project without the object behaves as both off.

## Project unit and public-viewer options

- `projectPatch.unit` on `confbuild_publish_checkpoint`/`confbuild_commit_edit` writes `project.unit` (`mm`, `cm`, `m`, `in` or `ft`), which the editor reads before any profile default. Furniture projects otherwise fall back to `cm`: send `unit: 'mm'` with the first checkpoint when the rows are authored in mm.
- `projectPatch.menuSettings` merges into `project.menuSettings`; keys you do not name keep their value. Writable: `showCartButtonInPublic`, `publicCartSettings`, `showSaveConfigButton`, `saveConfigButtonLabel`, `showBomButtonInPublic`, `publicBomSettings`, `showTechnicalDrawingsInPublic`, `publicDrawingSettings`, `showSpecialRequestInPublic`, `showQuoteRequestButtonInPublic`, `showSocialShareButtons`, `generateDrawingOnConfigSave`, `darkMode`, `bomCsvProfile`. Every other key, notably lead webhook/e-mail, `publicAccess`, `publicBotProtection`, editable public copies, customer price control/mode and embed branding, is rejected with an error naming it; the user sets those in the publish dialog.
- Read the current options with `confbuild_read_project` plus `includeMenuSettings: true`; lead webhook and e-mail come back redacted.

## Steel fabrication (DSTV-NC)

Steel members and plates are fabrication-ready when the NC data can be derived from the parametric rows, not from the mesh:

- Fixed-size rolled sections carry their catalog designation in `profile` (`IPE 200`, `HEB 300`, `UPE 200`, `UPN 160`, `L 80x80x8`, `SHS 100x100x5`, `RHS 200x100x6`); only members whose size comes from formulas leave `profile` empty and give `width`/`height`/`thickness` (the NC header then uses the model dimensions and reports `STEEL_SECTION_UNKNOWN`).
- Saw cuts: `startSlope`/`endSlope`, `jointTrim`, `autoconnect`, or `trimby … :miter`. Copes and notches: `subtraction` with a box operand. Holes: `fastenerHoleCutter` cylinders or `subtraction` with a cylinder operand, or the holes of `ibeamconnector` joints; square holes become `BO`, tilted holes additional planes `E0`–`E9` (at most ten drilling directions per part).
- Plates: `plate` rows, connector plates, thin steel `cube`/`extrusion` rows (≤ 80 mm). Sheet metal: `sheetmetal` with a steel material, holes as inner loops of the flat `contour`.
- Give every member and plate a steel material (`S235JR`, `S355J2`, …); otherwise the export default grade applies.
- Not NC-capable: mesh operands, cuts that only exist as CSG, holes across corners or root radii, holes or contours in round tubes.
- The BOM keeps differently machined steel parts in separate positions (fabrication signature), so each position is one NC file. With `dstvXnc`, welded-on plates become attached parts (W/A records) of their member and BOM bolts become S records.
- Channels (`uprofile`) need `exactChannelSection`; switch older projects with `confbuild_update_scene_settings` before building or exporting.
- Export with `confbuild_export_project` `format: 'dstv'` (options `dstvOrder`, `dstvDrawing`, `dstvPhase`, `dstvFileNamePattern`, `dstvMarkAttachments`, `dstvMarkBlock` `KO`/`PU`, `dstvEndCuts` `contour`/`sc`, `dstvXnc`, `dstvDialect`, `dstvNaming`). `confbuild_get_export_result` returns `dstvCheck`: `files`/`filesWithErrors` from the server-side NC validation, `positions` (ok/warning/error/skipped), `attention` (each position that is not ok, with its report codes) and `repairHints` per code. Repair the model for every `attention` position, export again, and report positions that stay `skipped` with their reason.

## Project scripting and animation

- Animation logic, camera/drone flights, pneumatic cycles, and button handlers live in project `scriptcode`; their visible controls live in INPUT rows. Read the script with `confbuild_read_project` plus `includeScriptCode: true`. Change an existing script with a `patch_scriptcode` operation (ordered `replacements` of unique `find` anchors → `replace`) inside `confbuild_apply_sheet_patch` or `confbuild_publish_checkpoint`; never resend a whole existing script for a local change - a full resend costs minutes of generation per edit and drifts from the stored copy. Use `projectPatch.scriptcode` only to create a new script or deliberately replace it completely; omit it to preserve the script and use an empty string only to remove it. Never keep a local copy of the script as the source of truth.
- Author and commit `scriptcode` through MCP only (`patch_scriptcode` or `projectPatch.scriptcode`). Never type it into the editor UI or execute it through browser evaluation/developer tools as a substitute.
- The script uses the editor's global `API`: parameters/cells, object animation, scene-object lookup, registered actions, input-row `ONCLICK`, reload-safe timers, pneumatic simulation, particles, and robot helpers. Camera flights animate `__threeCamera` and `__threeControls` in a cancellable `requestAnimationFrame` loop.
- Every requested animation must expose two separate visible INPUT buttons: Start and Stop. Their `ONCLICK` cells call stable `scriptcode` handlers with plain, non-awaited expressions, for example:
  `['animation_start', 'button', 'startAnimation', '', '', 'Start Animation', true, '', '', '', 'startProjectAnimation()', '']`
  `['animation_stop', 'button', 'stopAnimation', '', '', 'Stop Animation', true, '', '', '', 'stopProjectAnimation()', '']`
- Registered actions may supplement these controls but never replace either visible button. Start and Stop must be idempotent: Start prevents duplicate loops/timers/playback, and Stop immediately halts all motion resources owned by the animation while leaving a coherent current or resting pose and reload-safe cleanup.
- After every custom animation update, call `API.renderScene(true)` before scheduling the next update. Continuous scene rendering is disabled by default, so each `requestAnimationFrame`/timer step that directly changes an object, camera, controls target, robot pose, or other scene state must mutate first and then force exactly one render frame. Built-in managers such as `API.playAnimation()` already render through their per-update callback and must not be wrapped in a redundant second render loop.
- `async function ONLOADED()` establishes a coherent resting pose and must not auto-start motion. Motion starts only from the Start button (or an additional explicitly requested control). MCP renders prove the resting pose; `confbuild_run_project_interaction` then exercises Start and Stop in the live exact revision and returns before/after evidence plus script diagnostics. Inspect that evidence and report residual uncertainty only when the configured observation window cannot prove the full motion cycle.
- Scripts are event-driven, never polling: initialise once in `ONLOADED`, react to control changes through the INPUT rows' `ONCHANGE`/`ONCLICK` cells (`controlValue`) or `API.on()` listeners, and clean up with `API.disposeOnReload()`/`ONUNLOAD`. Never add `setInterval`/`setTimeout` loops that re-read parameters, cells, DOM or scene state to detect changes: every `getParam`/`getCell` is a worker round trip, and an idle project must cause zero worker traffic. Timers are reserved for visible motion owned by Start/Stop and never read the workbook per tick. When a handler needs several values, read them in one `ActiveWorkbook.getRangeValues(range)` call over the addresses from `API.findParamAddress()` instead of many single `getParam` calls.
- Scripts stay valid after every model rebuild (a hidden and re-added `PROJECT:`/`SHEET:` instance, any parameter change replaces scene groups): never keep an `Object3D` across clicks; resolve by outputid with `API.getSceneObject()` inside the handler, pass the live instance to `API.callSubproject(rowOutputId, fn, instance)` (the engine also injects it as `object`), subproject functions use `target || object` and key per-instance state by that object; `ONMODELUPDATED(detail)` (or the window event `confbuild:model-updated`) re-resolves targets and repairs pick planes after a rebuild, never a watchdog timer. Verify by toggling the instance's checkbox off and on and running the button again.
- Prefer extending existing scripts and keep output IDs/object names stable. A commit syntax error persists nothing.

## Patch addressing

- `sheetIndex` is zero-based.
- Rows/columns in patch arguments and A1 addresses are one-based.
- Supported operations: replace workbook, upsert/delete/rename/show sheet, set cells, replace/insert/delete rows, compact `upsert_sheet_tsv`, and keyed `upsert_output_rows` (rows or TSV). TSV parses finite numeric literals and preserves formulas/text; prefix structured cells with `json:`.
- Composite edits normally create or replace child sheets with `upsert_sheet`/`upsert_sheet_tsv`, then wire exact `SHEET: <name>` rows in the planned parent. Never send a sheet back that was read only in part (`truncated: true`, or listed in `autoWindowed.omittedSheetNames`): patch its rows with `set_cells`/`replace_rows`/`delete_rows`/`upsert_output_rows` instead. `upsert_sheet`, `upsert_sheet_tsv` and `replace_workbook` refuse (`SHEET_PARTIAL_REPLACE`), whatever was read before, to leave an existing sheet with fewer non-empty rows, to make an existing row id disappear (the trimmed first cell, counted per occurrence; `INPUTID`/`OUTPUTID`/`#` markers, `//` comments and formulas are no ids) even when the row count stays the same, to drop an existing sheet, or to take a sheet object that still carries `truncated`/`nextStartRow`, unless the operation sets `allowRowLoss: true`. Renaming ids in a whole-sheet rewrite needs `allowRowLoss: true` too; reordering, editing other cells and adding rows do not. The error lists up to 10 `missingIds` with `missingCount`; every applied shrink is reported as `SHEET_ROWS_REMOVED`, every applied id loss as `SHEET_ROW_IDS_REMOVED`. A sheet object in the `format: 'tsv'` read shape (`tsv`, no `data`) is parsed like `upsert_sheet_tsv`. The active `#` header for each parameterized reference must contain every planned child `inputId`, and the row must pass a non-empty literal or formula in that column.
- `insert_rows` inserts its `rows`; without `rows`, `count` inserts that many empty rows; with neither, the operation fails instead of inserting nothing.
- `replace_rows` without `count` replaces exactly as many existing rows as the replacement has — "replace rows 5–20 with 5 rows" would leave 11 old rows in place. Pass `count` (rows to remove before inserting) whenever the block shrinks or grows, e.g. `startRow: 5, count: 16, rows: [...5 rows]`.
- Row addresses are capped (50 000): a `row: 100000` typo would otherwise silently pad the sheet with empty rows.

## Authentication

The server uses the same normal user email/password path as repository Playwright automation. It reads `CONFBUILD_EMAIL`/`CONFBUILD_PASSWORD`, macOS Keychain service `codex-confbuild-playwright`, or `CONFBUILD_FIREBASE_CUSTOM_TOKEN`. It never returns credentials to the client and never defaults to a Firebase Admin service account.

The hosted Remote MCP uses OAuth authorization code with PKCE S256. Consent occurs in the signed-in confBuild web app; short-lived access tokens, rotating refresh tokens, persistent sessions, project operations, and render jobs stay bound to that Firebase UID. Tools additionally enforce the granted scopes: `mcp` for the protocol/prompt surface, `projects:read` for project/session reads, `projects:write` for mutations, and `render` for render/export jobs and artifact delivery. Starting a render or export requires both `projects:read` and `render`.

## Browser modes

- `attached`: connect to `CONFBUILD_MCP_CDP_URL`; never silently debug an arbitrary browser.
- `headed`: one visible Playwright Chromium context with an isolated profile per MCP transport under `output/playwright/confbuild-mcp/browser-profiles`. Retries reuse that context and profile; explicit `CONFBUILD_MCP_BROWSER_PROFILE` directories must not be shared by concurrent transports.
- `headless`: isolated local browser mode; it is not hosted server rendering.
- `auto`: attached when explicitly configured; otherwise headed, with no automatic headless fallback.
- `rendererMode: 'browser-tab'` is the render/export default. `rendererMode: 'server-headless'` plus `serverRenderingExplicitlyRequested: true` selects hosted server compute only when the user explicitly requested it; there is no automatic server fallback.
- Local modes use `reuseOpenTab: true` by default: exact project tab, same-project route alias, then empty startup tab. A different project's tab is never repurposed. Render/export work is serialized per exact project/configuration tab, not globally, so independent project tabs can run at the same time.
- Hosted MCP uses the host browser for lifecycle recovery and the exact-revision preview. Enumerate and retain the matching tab; follow SKILL.md Autonomous connection recovery instead of a fixed time cutoff. Never accumulate tabs, repurpose unrelated tabs, or use editor controls/page functions for semantic authoring. On connection proof, resume the authorized task automatically.

## Priced BOM and drawing schedule

`confbuild_plan_sheet_topology` accepts `manufacturingPlan.deliverables` in addition
to product, definitions and occurrences. Plan before applying prices or generating
drawings; keep planning-only requests free of geometry replacement/export claims.

- `bom`: one entry per definition with `definitionId`, positive `quantity`, `unit`
  (`stk|m|m2|m3|kg|l`), net `unitPrice`, three-letter `currency`, `priceBasis`
  (`unknown|estimate|user|supplier`), `source`, optional `supplier` and `notes`.
  Unknown prices require `unitPrice:null` and `priceBasis:unknown`; known prices
  require a source/calculation basis. Never fabricate prices, supplier links or
  verification dates. Zero means a genuinely free item. Count physical instances
  once, and do not price parent assemblies plus their children twice.
- `drawings`: stable `id`, `title`, `definitionIds`, `kind`
  (`overview|assembly|weldment|part|schedule`), `paperSize` (`A0`–`A4`), `views`,
  `dimensions` and `notes` arrays. Bind pages to known definitions, plan necessary
  sections/details and explicitly leave unknown tolerances/fits unresolved.
  Purchased parts stay in assembly/schedule pages, never manufacturing part pages.
- `assumptions`: short unresolved quantity, cost or drawing requirements.

The response's `deliverableSummary` contains currency-separated known subtotals,
unpriced definition ids, estimated-price counts and planned drawing count. It
performs no exchange-rate conversion. The plan persists with manufacturing topology
on project create/commit; pass `editSessionId` when revising an active edit plan.
Read the persisted project plan before updating it and preserve unaffected entries.

## Incremental manufacturing plan updates

`manufacturingPlan` is a complete replacement. Omitting it keeps a saved explicit
plan (`preservedSavedManufacturingPlan: true`) and regenerates a low-confidence
legacy plan only where none exists. For an existing plan, especially one with hundreds of
definitions, send `manufacturingPlanPatch` instead; never resend the whole plan
to change a few ids. `plan` may then be omitted (the current sheet plan stays),
and `manufacturingPlan` and `manufacturingPlanPatch` are mutually exclusive.

The patch merges into the newest plan: the edit session (`editSessionId`), else
the design session, else the plan stored on the design session's target project.

- `upsertDefinitions[]`, `upsertOccurrences[]`: full entries; an existing id is
  replaced completely, a new id is added.
- `removeDefinitionIds[]`, `removeOccurrenceIds[]`: unknown ids are only reported.
  An id may not be upserted and removed in the same patch.
- `cascadeOccurrences: true` also removes the occurrences of removed definitions.
  Without it, an occurrence that would point at a removed definition (or a removed
  parent occurrence) rejects the whole patch with
  `MANUFACTURING_PLAN_PATCH_DANGLING_REFERENCE`; nothing is saved.
- `syncFromRowMetadata: true` reads the workbook (edit session, else target
  project) and adds a definition for every row `manufacturingDefinitionId` missing
  from the plan: label from the row `name` column, `kind`, `makeOrBuy`,
  `drawingPolicy`, `partNumber`, `revision` and `process` from `metadata_json`
  (documented aliases such as `manufacturingMakeOrBuy`/`manufacturingDrawingPolicy`
  included; purchased forces `buy` + `bom-only`). It reports definitions no row
  references in `sync.unreferencedDefinitions`. Kept regardless: assemblies or
  weldments that have occurrences, definitions whose occurrence a row names or that
  parent other occurrences, definitions referenced by `deliverables`, and ids upserted
  in this patch (`sync.keptWithoutRowReference` gives the reason).
- `removeUnreferencedDefinitions: true` (only with `syncFromRowMetadata`) drops the
  reported definitions together with their plan occurrences.
- Optional `product`, `rationale` and `deliverables` replace those plan fields;
  `product` + `rationale` are required only when no plan exists yet.
- `dryRun: true` merges and validates, returns the report and saves nothing.

The merged plan passes the same schema as a full plan (unique ids, references,
purchased rule, deliverable references), else `MANUFACTURING_PLAN_PATCH_INVALID`
with `issues`. The result is `provenance: explicit`. The response carries
`manufacturingPlanSummary` and `manufacturingPlanPatchReport` (added, replaced and
removed ids, capped at 200 per list) instead of the full plan. With `editSessionId`
the next commit or checkpoint writes the plan to the project. Without it, the plan
stays in the design session and is written by the commit of the next
`confbuild_begin_edit` started from that session.

Typical repair of a drifted saved plan: `{ syncFromRowMetadata: true, dryRun: true }`,
review the report, then repeat with `removeUnreferencedDefinitions: true` and
`editSessionId`, then commit.

Planning does not assign prices to model rows. Apply known prices with sheet
columns `price`, `currency`, `priceUnit`, `priceSource`, `priceConfidence` and
optional evidence `priceSourceUrl`/`priceCheckedAt`; keep `metadata_json` manufacturing
bindings intact. Do not copy a total definition quantity onto every repeated row.
Reconcile the resulting built BOM with the plan, including stock/waste/fabrication
assumptions. Reuse `bom-json|bom-csv|bom-xlsx`, `cost-json` and purchasing/quote exports.
`drawing-pdf` with `drawingMode:saved` exports existing drawings; `standard` generates
standard views, not a verified custom manufacturing drawing set. Poll exports and
inspect results before claiming completion. Custom drawings still need the drawing
pipeline's generation, dimension/layout review and persistence checks.
