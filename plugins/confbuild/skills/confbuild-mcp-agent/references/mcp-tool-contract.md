# confBuild MCP tool contract

## Shared customer loop

- The installed plugin reads the packaged `references/model-loop.md` snapshot and starts sessions with `workflowSource: 'plugin'`; the server then omits runtime behavioral instructions.
- Direct MCP-only clients receive `references/model-loop.md` plus a compact Sheet-generation core in the default progressive bundle. They then load the selected profile and only the semantic prompt packs needed for the planned row types through `confbuild_get_prompt_sections`; explicit `essential`/`full` requests retain the legacy monolithic bundle.
- Both paths therefore use the same acceptance, native-part, validation, multi-view review (four default views, up to seven), repair, and stop-gate contract, but only an explicit plugin release changes an installed plugin's behavioral workflow.
- Local repository generators, Playwright artifact workflows, service accounts, and subagent requirements are intentionally outside the customer loop.

## State boundaries

- A design session stores request/profile context. In hosted mode, the exact start-session request and latest committed Sheet snapshot are additionally written to admin-only audit history; client reasoning, model messages, screenshot analysis, screenshots, and final free-text summary are excluded.
- Before create, clone, or begin-edit, the design session stores a mandatory `confbuild_plan_sheet_topology` result. `single-sheet` is reserved for one indivisible part. A `composite` plan declares the first orchestration sheet plus named functional `SHEET:`/`PROJECT:` children, parent ownership, repeated status, local datum, and child-specific input ids. Project creation seeds every planned embedded sheet immediately; the plan is copied into the edit session and may be revised explicitly by calling the same tool with `editSessionId`.
- An edit session stores a full hydrated workbook and its base storage revision in MCP-server memory. Every write to it is a compare-and-swap on the stored generation: two calls that loaded the same session concurrently cannot overwrite each other; the later one receives `EDIT_SESSION_CONFLICT` and must re-read. Never run two tool calls against one edit session in parallel.
- Sheet patches are local until `confbuild_commit_edit` or the composite `confbuild_publish_checkpoint` fast path.
- Retries are safe when they carry ids: `mutationId` on `confbuild_apply_sheet_patch`/`confbuild_publish_checkpoint`/`confbuild_commit_edit` makes a repeated call acknowledge the already applied/committed mutation (`alreadyApplied`/`alreadyCommitted: true`) instead of applying it twice; `confbuild_create_project` defaults its `idempotencyKey` to the design session, so a retried create resolves to the same project; an identical render/export of the same revision that is still running is returned as `reused: true` instead of being queued again.
- Long initial builds use adaptive coherent checkpoint commits as the progress channel. `confbuild_publish_checkpoint` combines patch, fingerprint-cached validation, revision-protected commit, and an in-place rebuild in the already connected clean editor tab. Invalid in-memory edits are retained for repair but never exposed as previews; a dirty tab refuses the update.
- Commits use the authenticated owner's private Firestore path and reject a changed base revision.
- Workbook validation returns a `topology` block and applies the declared plan as a commit gate. It rejects a missing/not-first main sheet, missing or unplanned child sheets, missing exact parent references, planned child inputs absent from the child or parent reference row, under-instantiated repeated children, and cyclic `SHEET:` graphs. Orphan child sheets are warnings even without a plan. `completionState=complete` additionally requires final scene diagnostics to name every planned embedded child and prove the planned subproject count.
- Large workbooks use a new generation-specific chunk prefix. The project manifest and its chunks are written atomically; older project-sheet chunks are cleaned afterward.
- Each commit stores the pre-commit workbook and project `scriptcode` together as a rollback snapshot in the same embedded-sheet subcollection under a dedicated scope; retention keeps the newest snapshots and prunes the rest after every commit. Snapshot protection is mandatory: legacy `snapshot: false` input is accepted but ignored, and a snapshot failure blocks the commit. Legacy workbook-only snapshots remain readable and explicitly preserve the current `scriptcode` when restored.
- Browser presence is the live preview, semantic-interaction, and capture channel, not the normal authoring surface. The connected app tab rebuilds MCP-authored revisions, claims interaction/render/screenshot jobs, and shows checkpoints to the user. Before a new project exists, `confbuild_prepare_browser` proves the assigned signed-in tab or a reusable dashboard or returns a dashboard `open-new` handoff. Once a target exists, it compares the exact project/configuration/revision with signed-in tab presence and returns the least disruptive `reuse`, `reload`, `navigate`, or initial `open-new` action (safe recovery replacements follow SKILL.md). The server records that open request per design session; while the tab is loading, later prepares return `tab-opening`/`reuse` instead of another `open-new`. Once any matching project/configuration tab exists, a dirty state blocks/waits rather than opening a duplicate. When several host tabs are visible, the host enumerates them and selects by exact project/configuration URL; the active, newest, or first-listed unrelated tab has no priority. The host retains that selected tab handle per design session, performs the tab-lifecycle action or the documented recovery exception, and repeats the call until `connected: true`; it never clicks editor controls, types project data, submits the prompt editor, or invokes page functions during normal operation. Project-authored INPUT buttons and named project/VBA functions/actions are exercised only through `confbuild_run_project_interaction`, whose backend-resolved selector is bound to the exact revision; it is not authorization for raw DOM clicks or arbitrary page evaluation. A different project/configuration or any tab with unsaved work is never repurposed or overwritten. Create, clone and restore enforce browser readiness server-side. Begin-edit/commit also accept a proven live, clean matching tab with a pending/failed model so a repair can be saved. Interaction/render/export still require the exact ready model. `browserConnected`, `modelReady` and `repairCanBeSaved` distinguish these states; `modelUpdates` identifies the automatic editor command and requires no user approval.
- The prepare-browser resource link is the agent navigation target and a manual fallback only for an actual user-action blocker. Follow SKILL.md Autonomous connection recovery, including its safe reload/replacement exception. Older server deadline/lifetime-tab prose is legacy client guidance; keep waits at most 25 seconds and honor actual backend gates. Match origin, project and configuration while ignoring transient query/hash fields.
- Multiple AI slots and MCP transport connections are supported concurrently. Each slot uses its own `designSessionId`, edit session, and retained exact project/configuration tab handle; there is no global active MCP tab. Independent sessions/projects may progress in parallel, but two mutations against the same edit session are rejected/serialized through its generation contract.
- The owner-visible editor connection record is per design session, not merely per OAuth client. It contains bounded ephemeral identity metadata only: MCP client name, reported agent client/model, optional host-provided `sessionLabel`, `designSessionId`, assigned tab id, project id, activity timestamps, and current tool. When no label is available, the editor shows a short session-id fallback. It contains no prompt, Sheet values, model messages, or reasoning and expires with the session.
- A UI mutation fallback is disabled by default. It requires a structured MCP result proving the exact semantic capability is unsupported, confirmation that no MCP tool covers it, and explicit user approval for one bounded UI action. Errors, timeouts, missing tabs, or browser unavailability never activate it. Return to MCP afterward. The confBuild AI prompt editor and provider-backed generation endpoints are never fallback surfaces.
- Render jobs are asynchronous so MCP client tool timeouts do not terminate browser work. `confbuild_get_render_result` long-polls server-side with `waitMs` (default 25 s, max 120 s — pick a value below your client's own tool timeout); a still-running answer carries `retryAfterMs` and the exact next call. Never start a second job for the same revision while one runs: a capacity refusal (`HEADLESS_USER_CONCURRENCY_LIMIT`) lists `activeJobIds` to keep polling. `diagnosticsOnly: true` builds the committed revision without screenshots and returns only the audit blocks — run it after checkpoints, never as a substitute for the visual review. Browser-tab rendering is the default and never falls back to server compute. `rendererMode: 'server-headless'` is valid only after an explicit user request, requires `serverRenderingExplicitlyRequested: true`, and still requires the exact browser connection.
- `confbuild_run_project_interaction` is a non-idempotent browser-tab job for persisted project behavior. `type: 'input-button'` resolves an exact `INPUTID`/optional sheet and executes only its stored `ONCLICK` or registered VALUE action; `script-function` accepts only a bare declared function name; `script-action` accepts only a registered action id. It awaits the callback, optionally observes delayed motion, returns before/after images, changed output transforms, active-animation summaries, and script debug/error evidence, and continues through `confbuild_get_render_result` if the first wait expires. Never pass or synthesize arbitrary JavaScript expressions.
- Render diagnostics include an approximate geometry audit, exact and unverified intersection findings, `outputIdAudit.rowsWithoutGeometry`, engine warnings, `diagnostics.scene.parts`, and `diagnostics.scene.subsheets` with exact child name, instance output id, descendant ids, mesh count, and world bounds. The `qualityGate` returns separate local output-id groups plus `requiredSubsheetNames`, `missingSceneSubsheetNames`, `remainingInspectionSubsheetNames`, and `suggestedInspectionSubsheetNames`. Every planned child sheet and every required defect/connection group needs revision-bound four-mode evidence; evidence for another target does not satisfy the completion gate. Pass `diagnosticsDetail: 'summary'` on routine polls to cap finding lists.
- `diagnostics.geometry.intersectionFindings` carries the engine's exact intersection preflight (OBB-SAT/CSG member overlaps) including a concrete fix `suggestion` per pair (which member yields, the exact `trimby=` cell to add). Treat these as first-class repair instructions — they are the same gate the local composite loop uses — and prefer them over re-deriving overlaps from screenshots.
- With the same project open in several tabs, a per-job claim lease makes exactly one tab capture; a tab that dies mid-capture is taken over after its lease expires.
- Edit sessions carry the project's saved configuration state so validation can flag VALUE cells that the editor will override (`VALUE_SHADOWED_BY_CONFIGMODEL`).
- The finish tool stores only content-free outcome enums (completion state, iteration count, fixed/residual defect categories); the free-text summary, `residualFindings`, and user-facing `residualReport` are never persisted in the audit log. For partial results pass the last completed render plus `stopReason` (`budget-exhausted`, `no-progress`, `user-requested`, or `blocked`). The report returns named pair evidence, total counts/truncation, and a continuation question. Include visual findings missed by diagnostics. Ask the user before extending an exhausted loop; resume with a fresh session on the same project URL after approval.
- Hosted usage telemetry stores content-free operational measurements only: authenticated user/client IDs, timestamps, tool/status/error code, duration, byte counts, Sheet operation/row/cell quantities, commits, project IDs, render/export jobs, and actual returned image/artifact blocks. Metadata-only screenshot descriptors are not counted as delivered images. Detail events expire after 90 days; daily per-user aggregates remain for trends. Client-side model tokens are not observable.
- MCP project provenance stores created/edited state, timestamps/count, agent client, optional client-reported model, profile, and MCP client name/version. It stores no prompt, Sheet values, screenshots, responses, or reasoning.

Profile selection belongs to the MCP client: classify the request yourself and pass an explicit `profile` (`building`, `machine`, `3dprint`, `structure` for halls/frames/trusses, `furniture`, or `generic`). `auto` falls back to a server keyword heuristic intended only for clients that cannot classify. Installed plugins pass `workflowSource: 'plugin'` and receive no prompt bundle. Direct MCP-only clients keep the default `workflowSource: 'server'` and `promptDetail: 'progressive'`: read the compact base, call `confbuild_get_prompt_sections` for every `progressiveLoading.requiredBeforeEditing` id, then fetch only packs relevant to the actual design. `essential` and `full` remain available for compatibility. Clients may pass `knownBundleHashes` on repeat sessions so a matching base bundle returns without its text, plus `knownSectionHashes` so unchanged base or progressively loaded sections omit their text.

Error results carry machine-readable `structuredContent` with `code`, optional `retryable`, and context (for example the current revision on `REVISION_CONFLICT`, the available sheet names on `UNKNOWN_SHEET_NAME`, the existing project on `DESIGN_SESSION_HAS_TARGET`, or `activeJobIds` on `HEADLESS_USER_CONCURRENCY_LIMIT`). Every expected failure has a code; `INTERNAL_ERROR` means the server logged the details and a single retry is appropriate. Most responses also carry `nextTool` (plus `nextToolArguments`) for the recommended continuation. The hosted endpoint rate-limits per user (HTTP 429 with `retry-after`); long-polling with `waitMs` instead of rapid polling stays well inside the limits.

Commercial exports reuse the built scene’s canonical BOM, price, purchasing, and quote services. Quote and purchasing exports fail closed on mixed currencies; quote also fails on missing required prices, while purchasing outputs remain usable and report estimated-cost coverage for unpriced lines. No exchange-rate conversion is inferred. `quote-pdf` additionally requires a configured seller identity: a meaningful company or seller name in `companyName` plus either a complete postal contact (`street` and `zipCity`) or a valid electronic contact (`email`, `phone`, or `website`). Commercial failures expose machine-readable codes such as `INVALID_SELLER_IDENTITY`, `MIXED_CURRENCIES`, or `MISSING_REQUIRED_PRICES` plus PII-free details (field names, missing requirements, positions, or currency codes rather than seller/customer values). The CO2 comparison uses generic cradle-to-gate material factors rather than EPDs and reports coverage. Dimension sorts are explicitly scene-axis extents (`boundsX`, `boundsY`, `boundsZ`, `boundsVolume`), because width/depth/height conventions vary between projects.

Pass the start tool's `designSessionId` to `confbuild_create_project`, `confbuild_clone_project`, and `confbuild_begin_edit`. Hosted mode retains a latest-session fallback for older clients, but the explicit ID is required for correct association when one user runs concurrent agents. Pass the exact public model identifier to start-session `model` only when it is known, and the exact user-visible host task/thread/chat title to `sessionLabel` only when the host exposes it; never infer either. The editor uses the returned `sessionIdentity` and falls back to the short design-session id. Installed plugin skills also pass their bundled `pluginVersion`; the response's `clientPackage` block reports whether that version is current and supplies the host-specific update command when an update exists. Direct MCP-only clients may omit it. The server never silently changes local client files.

## Scene settings

- `project.sceneSettings` is the part of a project no sheet row can express. Sheet rows may add `ambientlight`, `directionallight`, `spotlight`, and friends, but the base ambient/hemisphere/sun lighting, the environment map every material samples through `scene.environmentIntensity`, the background, and fog all live on the project document.
- Therefore a negative light row is not a way to darken a scene. Only the ambient channel cancels exactly (it is constant per fragment); a negative directional cancels only at the identical bearing, and there is no negative environment map at all.
- Night, dusk, and a real time of day come from `sunMode: 'solar'` with `sunDate`, `sunTime`, `siteLatitude`, `siteLongitude`, and `siteTimezoneOffset`: a sun below the horizon fades the directional light out and dims the environment dome to a night floor. In `sunMode: 'manual'` the dome stays at full brightness whatever the bearing.
- Read before you judge: `confbuild_read_project` with `includeSceneSettings: true` returns stored values, the effective values the editor will use, and the writable catalog with types, ranges, and defaults. Unknown keys and out-of-range values are rejected with a per-key error instead of being written through.
- Write either with `confbuild_update_scene_settings` (settings only, no workbook rewrite, no rollback snapshot needed because the previous values come back in the result) or with `projectPatch.sceneSettings` on `confbuild_publish_checkpoint`/`confbuild_commit_edit` when the look changes together with the model. Both merge: keys you do not name keep their value.
- `sceneSettings.exposure` exists in old documents but no renderer reads it; it is not writable and changing it would do nothing.
- `sceneSettings.steelFabrication` (`drillConnectionHoles`, `exactChannelSection`) is the one setting that changes geometry: the open tab rebuilds the model. New projects start with both on; a project without the object behaves as both off.

## Steel fabrication (DSTV-NC)

Steel members and plates are fabrication-ready when the NC data can be derived from the parametric rows, not from the mesh:

- Fixed-size rolled sections carry their catalog designation in `profile` (`IPE 200`, `HEB 300`, `UPE 200`, `UPN 160`, `L 80x80x8`, `SHS 100x100x5`, `RHS 200x100x6`); only members whose size comes from formulas leave `profile` empty and give `width`/`height`/`thickness` (the NC header then uses the model dimensions and reports `STEEL_SECTION_UNKNOWN`).
- Saw cuts: `startSlope`/`endSlope`, `jointTrim`, `autoconnect`, or `trimby … :miter`. Copes and notches: `subtraction` with a box operand. Holes: `fastenerHoleCutter` cylinders or `subtraction` with a cylinder operand, or the holes of `ibeamconnector` joints; square holes become `BO`, tilted holes additional planes `E0`–`E9` (at most ten drilling directions per part).
- Plates: `plate` rows, connector plates, thin steel `cube`/`extrusion` rows (≤ 80 mm). Sheet metal: `sheetmetal` with a steel material, holes as inner loops of the flat `contour`.
- Give every member and plate a steel material (`S235JR`, `S355J2`, …); otherwise the export default grade applies.
- Not NC-capable: mesh operands, cuts that only exist as CSG, holes across corners or root radii, holes or contours in round tubes.
- The BOM keeps differently machined steel parts in separate positions (fabrication signature), so each position is one NC file. With `dstvXnc`, welded-on plates become attached parts (W/A records) of their member and BOM bolts become S records.
- Channels (`uprofile`) need `exactChannelSection`; switch older projects with `confbuild_update_scene_settings` before building or exporting.
- Export with `confbuild_export_project` `format: 'dstv'` (options `dstvOrder`, `dstvDrawing`, `dstvPhase`, `dstvFileNamePattern`, `dstvMarkAttachments`, `dstvMarkBlock` `KO`/`PU`, `dstvEndCuts` `contour`/`sc`, `dstvXnc`, `dstvDialect`, `dstvNaming`). `confbuild_get_export_result` returns `dstvCheck`: `files`/`filesWithErrors` from the server-side NC validation, `positions` (ok/warning/error/skipped), `attention` (each position that is not ok, with its report codes) and `repairHints` per code. Repair the model for every `attention` position, export again, and report positions that stay `skipped` with their reason.

## Project scripting and animation

- Animation logic, camera/drone flights, pneumatic cycles, and button handlers live in project `scriptcode`; their visible controls live in INPUT rows. Read the script with `confbuild_read_project` plus `includeScriptCode: true`. Change an existing script with a `patch_scriptcode` operation (ordered `replacements` of unique `find` anchors → `replace`) inside `confbuild_apply_sheet_patch` or `confbuild_publish_checkpoint`; never resend a whole existing script for a local change - a full resend costs minutes of generation per edit and drifts from the stored copy. Use `projectPatch.scriptcode` only to create a new script or deliberately replace it completely; omit it to preserve the script and use an empty string only to remove it. Never keep a local copy of the script as the source of truth.
- Author and commit `scriptcode` through MCP only (`patch_scriptcode` or `projectPatch.scriptcode`). Never type it into the editor UI or execute it through browser evaluation/developer tools as a substitute.
- The script uses the editor's global `API`: parameters/cells, object animation, scene-object lookup, registered actions, input-row `ONCLICK`, reload-safe timers, pneumatic simulation, particles, and robot helpers. Camera flights animate `__threeCamera` and `__threeControls` in a cancellable `requestAnimationFrame` loop.
- Every requested animation must expose two separate visible INPUT buttons: Start and Stop. Their `ONCLICK` cells call stable `scriptcode` handlers with plain, non-awaited expressions, for example:
  `['animation_start', 'button', 'startAnimation', '', '', 'Start Animation', true, '', '', '', 'startProjectAnimation()', '']`
  `['animation_stop', 'button', 'stopAnimation', '', '', 'Stop Animation', true, '', '', '', 'stopProjectAnimation()', '']`
- Registered actions may supplement these controls but never replace either visible button. Start and Stop must be idempotent: Start prevents duplicate loops/timers/playback, and Stop immediately halts all motion resources owned by the animation while leaving a coherent current or resting pose and reload-safe cleanup.
- After every custom animation update, call `API.renderScene(true)` before scheduling the next update. Continuous scene rendering is disabled by default, so each `requestAnimationFrame`/timer step that directly changes an object, camera, controls target, robot pose, or other scene state must mutate first and then force exactly one render frame. Built-in managers such as `API.playAnimation()` already render through their per-update callback and must not be wrapped in a redundant second render loop.
- `async function ONLOADED()` establishes a coherent resting pose and must not auto-start motion. Motion starts only from the Start button (or an additional explicitly requested control). MCP renders prove the resting pose; `confbuild_run_project_interaction` then exercises Start and Stop in the live exact revision and returns before/after evidence plus script diagnostics. Inspect that evidence and report residual uncertainty only when the configured observation window cannot prove the full motion cycle.
- Prefer extending existing scripts and keep output IDs/object names stable. A commit syntax error persists nothing.

## Patch addressing

- `sheetIndex` is zero-based.
- Rows/columns in patch arguments and A1 addresses are one-based.
- Supported operations: replace workbook, upsert/delete/rename/show sheet, set cells, replace/insert/delete rows, compact `upsert_sheet_tsv`, and keyed `upsert_output_rows` (rows or TSV). TSV parses finite numeric literals and preserves formulas/text; prefix structured cells with `json:`.
- Composite edits normally create or replace child sheets with `upsert_sheet`/`upsert_sheet_tsv`, then wire exact `SHEET: <name>` rows in the planned parent. The active `#` header for each parameterized reference must contain every planned child `inputId`, and the row must pass a non-empty literal or formula in that column.
- `replace_rows` without `count` replaces exactly as many existing rows as the replacement has — "replace rows 5–20 with 5 rows" would leave 11 old rows in place. Pass `count` (rows to remove before inserting) whenever the block shrinks or grows, e.g. `startRow: 5, count: 16, rows: [...5 rows]`.
- Row addresses are capped (50 000): a `row: 100000` typo would otherwise silently pad the sheet with empty rows.

## Authentication

The server uses the same normal user email/password path as repository Playwright automation. It reads `CONFBUILD_EMAIL`/`CONFBUILD_PASSWORD`, macOS Keychain service `codex-confbuild-playwright`, or `CONFBUILD_FIREBASE_CUSTOM_TOKEN`. It never returns credentials to the client and never defaults to a Firebase Admin service account.

The hosted Remote MCP uses OAuth authorization code with PKCE S256. Consent occurs in the signed-in confBuild web app; short-lived access tokens, rotating refresh tokens, persistent sessions, project operations, and render jobs stay bound to that Firebase UID. Tools additionally enforce the granted scopes: `mcp` for the protocol/prompt surface, `projects:read` for project/session reads, `projects:write` for mutations, and `render` for render/export jobs and artifact delivery. Starting a render or export requires both `projects:read` and `render`.

## Browser modes

- `attached`: connect to `CONFBUILD_MCP_CDP_URL`; never silently debug an arbitrary browser.
- `headed`: one visible Playwright Chromium context with an isolated profile per MCP transport under `output/playwright/confbuild-mcp/browser-profiles`. Retries reuse that context and profile; explicit `CONFBUILD_MCP_BROWSER_PROFILE` directories must not be shared by concurrent transports.
- `headless`: isolated local browser mode; it is not hosted server rendering.
- `auto`: attached when explicitly configured; otherwise headed, with no automatic headless fallback.
- `rendererMode: 'browser-tab'` is the render/export default. `rendererMode: 'server-headless'` plus `serverRenderingExplicitlyRequested: true` selects hosted server compute only when the user explicitly requested it; there is no automatic server fallback.
- Local modes use `reuseOpenTab: true` by default: exact project tab, same-project route alias, then empty startup tab. A different project's tab is never repurposed. Render/export work is serialized per exact project/configuration tab, not globally, so independent project tabs can run at the same time.
- Hosted MCP uses the host browser for lifecycle recovery and the exact-revision preview. Enumerate and retain the matching tab; follow SKILL.md Autonomous connection recovery instead of a fixed time cutoff. Never accumulate tabs, repurpose unrelated tabs, lose unsaved edits, or use editor controls/page functions for semantic authoring. On connection proof, resume the authorized task automatically.

## Priced BOM and drawing schedule

`confbuild_plan_sheet_topology` accepts `manufacturingPlan.deliverables` in addition
to product, definitions and occurrences. Plan before applying prices or generating
drawings; keep planning-only requests free of geometry replacement/export claims.

- `bom`: one entry per definition with `definitionId`, positive `quantity`, `unit`
  (`stk|m|m2|m3|kg|l`), net `unitPrice`, three-letter `currency`, `priceBasis`
  (`unknown|estimate|user|supplier`), `source`, optional `supplier` and `notes`.
  Unknown prices require `unitPrice:null` and `priceBasis:unknown`; known prices
  require a source/calculation basis. Never fabricate prices, supplier links or
  verification dates. Zero means a genuinely free item. Count physical instances
  once, and do not price parent assemblies plus their children twice.
- `drawings`: stable `id`, `title`, `definitionIds`, `kind`
  (`overview|assembly|weldment|part|schedule`), `paperSize` (`A0`–`A4`), `views`,
  `dimensions` and `notes` arrays. Bind pages to known definitions, plan necessary
  sections/details and explicitly leave unknown tolerances/fits unresolved.
  Purchased parts stay in assembly/schedule pages, never manufacturing part pages.
- `assumptions`: short unresolved quantity, cost or drawing requirements.

The response's `deliverableSummary` contains currency-separated known subtotals,
unpriced definition ids, estimated-price counts and planned drawing count. It
performs no exchange-rate conversion. The plan persists with manufacturing topology
on project create/commit; pass `editSessionId` when revising an active edit plan.
Read the persisted project plan before updating it and preserve unaffected entries.

Planning does not assign prices to model rows. Apply known prices with sheet
columns `price`, `currency`, `priceUnit`, `priceSource`, `priceConfidence` and
optional evidence `priceSourceUrl`/`priceCheckedAt`; keep `metadata_json` manufacturing
bindings intact. Do not copy a total definition quantity onto every repeated row.
Reconcile the resulting built BOM with the plan, including stock/waste/fabrication
assumptions. Reuse `bom-json|bom-csv|bom-xlsx`, `cost-json` and purchasing/quote exports.
`drawing-pdf` with `drawingMode:saved` exports existing drawings; `standard` generates
standard views, not a verified custom manufacturing drawing set. Poll exports and
inspect results before claiming completion. Custom drawings still need the drawing
pipeline's generation, dimension/layout review and persistence checks.
